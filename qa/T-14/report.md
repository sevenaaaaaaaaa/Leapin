## 1 前置

- [ ] 用本分支构建并启动 App（`swift build --scratch-path /tmp/t14-scratch --disable-sandbox`，再开 App）。
- [ ] 当前配置里至少有一个可选策略组（没有的话 S2 的「改成走公司」无出口可选，先换一份配置）。
- [ ] 目标站点用 `api.company.com` 或任一真实打不开的内网站点；记下它在「为什么」里实际走的 policy。
- [ ] 关掉菜单栏面板与实时浮窗，确认首屏五个事实不依赖它们（T-08 评审 B-1 的修法）。

## 2 走查步骤

| # | 动作 | 期望看到 | 实际（填） |
| --- | --- | --- | --- |
| 1 | 在「怎么判」里选一条能取到 host 的规则，点「为什么」 | 「为什么」打开在连接 tab，搜索框已带该 host（T-07 注入） | |
| 2 | 清空搜索框，输入目标 host，看列表 | 该 host 的连接在列表里，点开能看到它命中的规则与 policy | |

## 3 计时模板（S2 目标 ≤ 90 秒）

从「用户决定要查这个站点」开始，到「看到重测结果并确认已通」结束。用秒表，记到 0.1 秒。

| 节点 | 说明 | 时间戳 |
| --- | --- | --- |
| t0 | 开始：切到「为什么」 | |
| t1 | 输入 host 完成 | |
| t2 | 命中链与出口可见 | |
| t3 | 打开「改成走公司…」 | |
| t4 | 保存并开始重测 | |
| t5 | 重测结果出现（成功或明确失败原因） | |

- 输入耗时 = t1 − t0
- 首屏理解耗时 = t2 − t1
- 改路 + 重测 = t5 − t3
- **S2 总耗时 = t5 − t0**，判定：≤ 90 s 通过；> 90 s 记下卡在哪一段。

## 4 判定与记录
