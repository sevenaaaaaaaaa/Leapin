## 4 取舍（每条：争点 → 选项 → 裁定 → 代价）

### 4.1 W1 先做，W2/W3 等评审后才写任务行（CRD 0001，用户定）

- **争点**：三波是并行排、还是串行排。
- **选项**：一次排完 W1–W3；或先做 W1、评审后再写 W2/W3 的任务行。
- **裁定**：串行。W2 的四页重排全部复用 W1 的 token 与页头，晚做等于把四页改两遍。
- **代价**：W1 是全仓横向改动（字号、玻璃、选中态），一次性大 diff；单测虽不受影响，仍要整轮重跑确认。CRD 0001 记了这两条。

### 4.2 六处 QA 断言从「形态」改成「行为」（CRD 0002，用户选 A）

- **争点**：M2 的断言锁的是控件与函数名（segmented Picker、`factCell(`），而 W2 要换的正是形态——照设计改必红，不改就违反 §12。
- **选项**：A 断言判「入口存在 / 标签存在 / 可切换」，每条做一次红测；B 冻结形态、W2 只调样式。
- **裁定**：A。B 会让 §12 第 1、5 条永远红，M2.5 的 DoD 实质降级。
- **代价**：改 `qa/T-07` C2/C9、`qa/T-08` C2、`qa/T-09` C4 等六条，每条都要证明改后仍能红（对 `99090da` / `03a90aa` 红、对新提交绿）。后续追加第七处：`qa/T-01` C4 的菜单栏宽度从「钉 276」改成「钉设计值 280」（见 4.8）。

### 4.3 首屏不做「最近决策」栏（ADR 001，PM 定，用户授权接手 T-17 余项）

- **争点**：§9 要证据区两栏（最近决策 7 : 场景 5），首屏只有场景一块。
- **选项**：A 拿现有计数拼一条「最近拦截 N 次」；B 新建决策历史（引擎事件流 + 存储 + 裁剪）；C 先不做。
- **裁定**：C。仓库里没有任何「谁、何时、依据哪条规则、去了哪个出口」的记录，A 会产出「看起来像历史、其实是当下事实」的行——首屏是最不该编的地方；B 比 T-17 本身还大，属于偷加数据层。
- **代价**：§9 的 7:5 只兑现了 5 那一半；要补得先有一条决策记录源，那是一条独立任务。

### 4.4 ink 焦点带只出现在首屏，其余三页用「表 / 查询条 / 过滤条」当主视觉

- **争点**：§7 的构图模板写「每页同一骨架：页头 / 焦点带 / 证据区」，但 §4 第 1 条写的是「一个墨色焦点带（**或**一张主图 / 一条主曲线）」，§9 的逐页方案里也只有「走哪」有焦点带。
- **裁定**：按 §4 + §9 落地——只有首屏一个 ink 带；怎么判用表、改成什么用过滤条+列表、为什么用查询条+垂直路。`FocusBand` 的实际使用点只有 `DashboardView.swift:232` 一处。
- **代价**：§7 的模板文字与实现不一致，是文档内部矛盾，不是实现偷懒；要消它得改 §7 的措辞（见缺口 B1 / B2）。

### 4.5 怎么判保留策略 chips，不把策略组搬进主表（T-18 收窄）

- **争点**：任务书写「过滤条 = 全部 / 策略组 / 规则」。
- **裁定**：保留原有的策略 chips（全部 / 直连 / 代理 / 拦截）。把策略组搬进主表会改掉 T-10 的「策略组在右栏」契约，那是另一条任务。
- **代价**：§9 过滤条的字面没兑现；已写在 T-18 的进度行里，不留给下一个人猜。

### 4.6 「行 hover 才出动作」不适用（T-18 收窄）

- **事实**：`RuleRow` 只显示、不带动作，动作在行尾菜单与 ⌫ / 空态写入口里（T-10 C7 已判过）。

### 4.8 菜单栏面板宽度：设计值 280 优先于既有实现值 276（T-20 / CRD 0002 追加）

- **争点**：`qa/T-01` C4 把宽度钉成 276，设计 §9 写 280。
- **裁定**：以设计值为准改代码，同时把断言改成钉 280（其它宽度仍红），并对 `99090da` 核对过（那份 276，新断言会红）。
- **代价**：一次断言改写 + 一次红测；换来「断言钉设计值、不钉当时的实现值」这条口径。

### 4.9 图标换成「一条路」母题，生成脚本入仓（T-21）

- **裁定**：墨底 squircle + 三点一线、中点朱红；色值从 `Theme.swift` 同源取，`scripts/make-icon.py` 生成 16–1024 全套 `.icns` 与 1024 源图。
- **代价**：图标是位图，脚本是唯一可复现来源；改 Theme 的墨色/朱红必须重跑脚本，否则图标与界面会漂移。

### 4.10 M3（iOS 语义）暂缓（用户 2026-11-24 裁定）

- **裁定**：先走 v5（M2.5 的 W1 → W2 → W3），M3 之后再判断要不要做、要不要提前。
