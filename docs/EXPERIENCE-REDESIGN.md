# Leapin 产品与交互方案 v2：总览 Dashboard、场景、多内核与网络生态

更新日期：2026-11-11。

状态：本文件同时记录完整目标和分批交付。当前已完成总览 Dashboard、六类场景的配置绑定、本地书签和原生 / Mihomo 导入执行闭环；Tailscale、完整场景优化、自主日志分析和通用插件仍未实现。具体实现边界与验证见第 16 节。

## 1. 已确认的产品方向与上一轮偏差

总览是首页、导航与便捷操作台：场景在前，功能小组件在前，常用操作在前。连接明细、完整日志、抓包记录和诊断过程进入独立工作区。Agent 嵌入任务，承担识别、配置、执行、验证和恢复。

上一轮错误地把总览替换成任务输入与诊断页，并将部分能力做成“入口 → 文字计划 → 再跳转原页面”。这没有满足首页要求，也没有体现实质的 UI / UX 差异。已有文档中“功能导航不能降低任务难度”的判断不能用来覆盖用户明确要求。

本轮用户进一步确认：

- “机场转化”指代理订阅格式转换与兼容性检查。
- “mihoo CLI”指 Clash / Mihomo 等代理内核的命令行运行模式；原生引擎不支持时，通过可视化管理的外部内核提供能力。
- 总览必须有海外 Agent、开发、娱乐、综合、出国、私密等场景快捷切换。
- 新增 Tailscale 一键回家、浏览器书签、统一数据导入、指定 URL 网络配置评估、一句话增加配置、自动排障、自主日志分析与网络插件生态。

产品定位：**一个可以切换场景、管理网络资源、调用多种内核，并帮助完成配置和排障的个人网络工作台。**

## 2. 总览与完整信息架构

### 2.1 总览首屏结构

| 区域 | 主体内容 | 直接操作 |
| --- | --- | --- |
| 顶部状态条 | 当前场景、正在使用的内核、连接状态、需要处理的异常 | 连接 / 暂停、异常处理 |
| 场景切换区 | 综合、海外 Agent、开发、娱乐、出国、私密；自定义场景 | 切换、查看变化、恢复上一场景 |
| 主要小组件 | 订阅与线路、回家、常用书签、开发网络、网络体检、隐私与抓包 | 组件内完成常用动作 |
| 固定与最近 | 用户置顶的 App、URL、NAS、SSH、插件动作 | 打开、连接、检查、重复执行 |
| 能力与扩展 | 当前内核支持范围、缺少的依赖、插件入口 | 查看协议兼容性、管理内核与插件 |

首页没有固定的大聊天框和默认连接明细表。Agent 作为全局入口、小组件内的上下文动作和异常解决入口。诊断可以在独立面板或抽屉展开，完整过程进入排障工作区。

小组件有明确的尺寸和任务分工：场景横条负责切换；回家组件负责设备与资源；订阅组件负责来源、更新和线路选择；书签组件呈现常用目标；网络体检组件只显示待处理问题及下一步。避免所有组件都变成“图标＋介绍＋前往”。支持固定、隐藏、排序与恢复默认布局；首版采用稳定的预设布局，避免先投入复杂的自由拖拽系统。

## 3. 场景是真实的配置组合

完整场景的目标模型包含目标 App / 服务、分流偏好、所需内核、线路选择、DNS、局域网与 tailnet 例外、终端配置、日志和抓包偏好、验证目标；本轮首批仅实现配置绑定与切换。场景展示“已就绪 / 缺少条件 / 已调整 / 验证失败”，不能只保存一个场景名称。

| 场景 | 首要目标 | 主要配置与验证 |
| --- | --- | --- |
| 海外 Agent | AI API、Agent CLI、网页服务与长时间任务稳定访问 | 相关服务分流、稳定出口偏好、终端代理、服务连通性；不只比较一次延迟 |
| 开发 | 代码、依赖、容器、服务器与本地服务协同 | Git / 包管理器 / 选定终端配置、本地与内网绕过、DNS、服务器和调试入口 |
| 娱乐 | 流媒体、游戏与娱乐服务 | 按服务选择线路、访问检查、UDP 及当前接管范围说明；没有相关能力就显示限制 |
| 综合 | 日常混合使用 | 通用分流、广告过滤、回退与内网访问 |
| 出国 | 海外环境访问国内及当地服务 | 根据所在地与目标服务选择方案，保留登录门户和家庭资源访问 |
| 私密 | 减少跟踪和不必要的数据留存 | 加密 DNS、过滤、抓包与日志留存偏好；明确未被代理接管的流量 |

首次切换可展示简短差异；常用切换在既有授权与范围内直接执行。涉及新的系统接管范围、出口或证书信任时按实际影响交代。失败恢复此前状态；不通过关闭 TLS 校验来换取“成功”。

## 4. 多内核：协议覆盖与可视化 CLI

### 4.1 用户看到的能力

普通用户看到“这份订阅能否使用、是否需要其他内核、当前线路是否通过检查”。专业用户展开查看内核、版本、协议、传输方式、UDP、TLS / Reality、TUN 与平台要求。

能力矩阵必须区分四个维度：

1. 格式识别与参数保留。
2. 当前原生引擎的实际拨号能力。
3. 某个已安装、已适配版本的外部内核能力。
4. 本机依赖、授权、配置、服务端与真实网络共同决定的实际可用性。

不能将“可导入”显示为“支持连接”，也不能将某个内核文档中的全部能力当作当前 App 已集成。协议、传输、加密组合、系统能力与测试结果应分别列出。

### 4.2 实现结构

前端与 Agent → 类型化场景 / 任务 → 能力解析器 → Native / Mihomo / 后续内核适配器 → 统一状态、连接与日志。

第一优先接入 Mihomo。需求梳理阶段做过版本与帮助检查：`mihomo` 1.19.25 可执行，帮助包含 `-v`、`-t`、`-f`、`-d`、控制器地址与 secret 参数。当时没有启动内核；本轮已完成受管运行及本地链路测试，见第 16 节，仍未验证真实机场节点。

适配器约定：发现版本、报告能力、预检配置、启动、就绪检查、应用配置、选择策略、列连接、测速、订阅日志、停止和恢复。Mihomo 的进程生命周期由 CLI 管理；策略、连接、日志等结构化控制优先使用其控制 API，而不是解析终端打印内容。

适配器要处理：

- 外部内核的配置预检、独立工作目录、进程归属、崩溃与退出恢复。
- 控制接口的本地边界、认证和版本差异。
- 代理 / DNS 端口、TUN 路由与系统代理的资源所有权；任一时刻由明确的协调器决定谁接管。
- 切换前后分别检查；不能把系统代理指向尚未就绪的内核，失败时恢复旧路径。
- 管理接口、订阅下载、tailnet 与测试流量的路径标记，避免回环或相互代理。
- 对 CLI 使用固定执行文件与参数数组，提供超时、取消、输出上限和错误分类；自然语言不能直接拼接为 shell 命令。

外部内核配置保留原始来源与其专属字段。通用场景通过可审查的 overlay 或目标内核编译器应用，不能先强行降级成当前原生 Profile 后再声称兼容。

## 5. 机场订阅转换与兼容性检查

完整路径：粘贴订阅 / 导入文件 → 隔离下载与解析 → 来源与格式识别 → 选择目标格式与运行内核 → 检查信息损失和执行能力 → 显示差异 → 验证 → 导出或启用。

支持格式分阶段登记，以实际转换器为准：Clash / Mihomo YAML、Surge conf、节点 URI 列表、base64 订阅、Leapin JSON；后续格式通过插件增加。

兼容性结果至少分为：原生可执行、外部内核可执行、有信息损失、目标不支持、未知 / 未验证。按节点和字段解释原因，不用一个总的“导入成功”遮盖不可拨号节点。

转换不能凭空让目标客户端支持缺少的协议。用户可选择保留节点、改用兼容内核，或在看清损失后导出目标可表达的子集。订阅凭据不默认发给公共转换服务。

更新订阅时区分上游原始内容与本地修改，显示新增 / 删除 / 变化节点，保留场景引用并处理已消失的节点。启用前失败不覆盖现有配置。

验收：同一份混合协议订阅在原生和 Mihomo 目标下生成不同的执行能力报告；Surge 无法表达的字段不被静默丢弃；转换成功与真实连通分别记录。

## 6. Tailscale 一键回家

首页“回家”组件呈现家庭目标、可访问资源和真实状态。首次设置选择家庭设备 / 子网与资源，之后可以从总览进入家庭 NAS、SSH 或 Web 管理页。

应分别处理：直接访问 tailnet 设备、通过已配置并获准的子网路由访问家庭内网、使用家庭 exit node 作为互联网出口。子网访问与全互联网出口是不同范围，不能合并成含糊的“已回家”。

状态路径：未安装 → 服务未就绪 → 待登录 → 待选择家庭目标 / 路由 → 设备离线 / 权限或路径异常 → 资源可达。

“一键”发生在首次配置、登录与所需网络授权完成以后。家里没有在线设备或子网路由时，引导完成缺失条件，不能给出假成功。不要默认发布公网服务或修改远端 tailnet 权限。

适配器优先使用版本探测、结构化状态、目标 ping / 资源端口检查；必要偏好改动用当前版本支持的命令执行并回读。恢复只撤销本任务拥有的改动，不能简单 down 掉用户已有的工作 tailnet。

本机发现 `tailscale` 1.104.5；仅确认二进制和帮助可用，没有读取设备清单、发起登录、修改路由或验证家庭连接。

## 7. 浏览器书签与统一数据导入

### 7.1 网络书签

支持粘贴 URL、手动添加、浏览器导出的 HTML 书签以及后续浏览器扩展分享。书签可以绑定场景、线路偏好和家庭资源身份；从总览直接打开、检查或修复该目标。

浏览器原始书签与 Leapin 网络偏好分开保存。打开默认使用指定 / 默认浏览器；应用级或系统级代理无法天然保证单个浏览器标签页的独立出口，需由域名分流或明确的浏览器隔离机制提供，不可误导。

### 7.2 统一导入中心

入口支持文件、拖拽、粘贴和浏览器分享。导入类型包括配置 / 订阅、书签、规则与过滤列表、应用偏好、NAS / SSH 资源、场景、诊断日志或 HAR；每种类型由独立导入器报告支持程度。

流程统一为：识别 → 解析 → 去重与匹配 → 差异 / 冲突预览 → 选择合并或新建 → 验证 → 完成与恢复。

书签按规范化 URL 与文件夹合并，配置按来源与稳定身份合并；敏感查询参数和用户明确指定的不同资源不能因粗暴 URL 归一化丢失。首版由用户提供导出文件，不默认读取整个浏览器用户目录或浏览历史。

## 8. 粘贴特定 URL，评估网络配置

URL 入口首先识别普通网站、订阅、设备资源和其他可处理链接，再进入相应流程。订阅链接不得被误当网页测试并输出含 token 的完整地址。

普通目标检查当前分流与实际执行内核、DNS、代理连接、TLS / 证书、HTTP，以及用户选择的直连 / 候选线路对照。结果按层标记成功、异常、未执行和不适用。

默认做站点连通性检查，不携带粘贴链接中的路径、查询参数与身份信息。用户需要评估某个特定 API / 页面路径时，明确选择测试完整目标并展示脱敏范围；不能把 origin 检查结果称作特定接口已可用。

书签、场景与排障复用同一个目标对象：检查结果可以转为目标分流偏好、加入场景或保存为书签。HTTP 403、需要登录、证书问题和网络超时是不同类别；一次连通不能证明账号、流媒体授权或完整 Agent 任务可用。

验收：用户从总览粘贴 URL，获得可追溯的当前路径与候选方案；任何自动生成规则都绑定明确目标和检查证据。

## 9. 一句话增加或修改网络配置

示例需求：

- “让 Claude Code 使用工作线路，国内依赖和局域网保持直连。”
- “把这个机场订阅转换为 Mihomo 配置，检查有哪些节点可用。”
- “回家访问 NAS，保持其他网络方案不变。”
- “让这个网站直连，其他网站继续使用当前方案。”

理解器产出类型化计划，包括目标、作用范围、需要的内核 / 插件、缺失输入、配置差异、验证步骤与恢复点。已有对象可自动解析；缺少订阅、账号、家庭目标或有效线路时只询问必要信息。

计划通过能力检查与版本前置条件后由执行器落地。完成后验证实际路径，不只检查文件已写入。终端型 Agent 需要对选定命令或环境生成并应用合适的代理配置，不能假设所有 CLI 都遵循 macOS 系统代理。

日常已授权动作可直接完成；不为打开书签、发现设备等动作再插入一个只有文字的计划页。涉及实际配置变化时将差异和影响范围放在相应操作位置。

## 10. 自动排障与自主日志分析

### 10.1 代理失败

检查服务与监听端口、系统代理指向、内核存活、配置版本、DNS、规则 / 策略、协议组合、节点握手、TLS 和 HTTP。使用对照探测区分目标服务、当前线路与本机设置问题。修复以局部范围为先，并记录执行前后证据。

### 10.2 抓包失败与本地 HTTPS 解密失败

检查流量是否经过支持抓取的路径、抓包状态、目标主机范围、CA 是否生成 / 过期 / 受信任、TLS 握手、HTTP 版本和客户端证书固定。外部内核的连接日志不等于 HTTP 明文抓包；适配器必须分别声明流量观测与解密抓包能力。

不支持的 HTTP 版本或证书固定明确显示边界；不通过关闭上游证书校验或静默信任根证书修复。证书信任相关操作保留明确的用户动作。

### 10.3 疑似非预期中间人

与用户主动开启的本地 MITM 分开显示。收集证书链、信任状态、域名、有效期、已知本地代理和受控对照路径的证据。证书变化本身不等于攻击，企业代理和登录门户也可能改变路径；证据不足时只报告异常与待确认项。

### 10.4 日志分析

统一事件包含时间、来源内核 / 插件、场景、配置版本、目标、连接或任务关联 ID、阶段和错误码。收集相关时间窗，去重、聚类并关联配置变化，输出“现象 → 证据 → 候选原因 → 验证 → 修复结果”。

先执行确定性规则和网络探测；大模型可以解释与提出假设，但不能把推断标成已证实。分析前脱敏 URL、凭据与请求头，控制日志留存。默认本地处理；接入远端模型时单独说明和控制可发送范围。日志、导入文件和网页内容是数据，不能成为给执行器的新指令。

低风险只读检查在任务授权范围内自动执行。修复使用有界重试、配置快照和恢复点；连续失败停止反复切换，保留已验证事实，提供可分享的脱敏诊断包。

## 11. 插件生态与统一能力注册

插件可以贡献内核、导入 / 转换器、诊断器、日志解析器、Tailscale 等连接器、场景模板、书签动作及首页小组件。每个贡献都挂到统一能力注册表，避免只有一个孤立插件目录。

注册信息至少包含：插件 ID 与版本、兼容宿主版本、执行入口、依赖、贡献类型、动作输入 / 输出 schema、能力声明、所需权限、超时 / 取消、健康检查和更新来源。

动作结果统一携带实际执行者、状态、证据、配置变更与恢复信息，供首页、场景和 Agent 共用。

执行器按声明范围开放网络探测、日志读取、文件读写、内核控制、系统网络设置和凭据引用。第三方插件与 UI 进程隔离；崩溃不能带走代理。核心系统接管和配置写入由宿主协调，不能靠插件任意抢占。

插件安装、来源 / 版本校验、升级失败恢复、禁用 / 卸载与剩余配置归属需要明确处理。首期先用内置适配器验证契约，再开放受控第三方插件；不先建设一个没有可运行扩展的商店。

- 向导修改只有服务检查和运行规则更新完成才确认；运行规则更新失败恢复原绑定。绑定文件 0600，本轮不将它同步到其他设备。
- 命令面板增加“回家 · Tailscale”“管理与导入浏览器书签”“检查本地代理与日志”；有限本地任务词表认识“回家”。

### 书签是可复用目标

- 常用书签管理页导入浏览器导出的 Netscape HTML 或 Chromium 书签 JSON，先显示新增、重复、跳过和前 100 个候选。
- 保留文件夹标签、完整路径 / 参数 / 片段；对域名大小写、默认端口与空根路径做去重，不把不同查询参数当成同一地址。
- 仅保留有效 HTTP / HTTPS 链接；跳过脚本、本地文件和 URL 登录凭据。HTML 按文本解析，不运行脚本、不加载外部资源、不读取浏览器配置目录。

### 排障结果可以直接行动

- “检查本地代理”与“排查抓包与解密”读取状态和日志，不访问外部网站；连接网络失败后自动生成本地检查结果。
- 目标网站检查组合当前规则解释、DNS、直连 GET 和显式本地代理 HEAD。只测试 origin，不带原链接的路径 / 参数 / 片段或认证凭据。服务、配置、家庭资源或系统接管在检查期间变化时，结果标为过期。
- 分开表达服务停止、端口冲突、内核未就绪、系统未接管、DNS 失败、代理请求失败、HTTP 错误、站点不支持 HEAD、抓包关闭、HTTPS 解密未开启、CA 文件缺失和没有请求样本。
- CA 文件存在不等于客户端已信任；TLS 日志不证明中间人攻击；405 / 501 不直接判断代理损坏；GET 与 HEAD 的差异明确展示。

- 复制检查摘要不含原始日志样例。动作只来自类型化入口：连接、设置、抓包、方案；不会执行日志里的命令或自动关闭校验。

### TUN：终端执行与图形端预检导出

- 新增 `leapin tun --source ... [--check] [--kernel ...]`。普通用户可调用真实内核预检；启动前检查管理员权限，不会偷偷提权或以 root 启动图形 App。
- 显式 TUN 会话使用自有 utun 名、内核自动路由、DNS 劫持与回环 / tailnet 地址段排除；内核控制接口与 TCP 监听仍限定本机。
- 运行成功要求自有设备名已出现；终端在启动前安装 Ctrl-C / SIGTERM 处理，等待自有内核退出后再清理私有临时目录，避免父进程提前退出丢失异步清理。未安装签名特权服务，不作为图形版一键 TUN 完成。

- 本轮未运行管理员 TUN，不对真实网卡 / 路由恢复、全设备 UDP、休眠和其他 VPN 共存作验收结论。DNS / 路由恢复属于下一阶段真机验收。

### HTTPS 调试任务

- 总览 / 命令面板 → 选定网站 → 独立 mitmdump → 当前 Mihomo HTTP 入口 → 目标服务。当前 App 需手动设置独立 HTTP 代理，未实现自动按 App 接管。
- 对指定主机解密，其余站点保持隧道；上游 TLS 校验保持开启，可显式指定不含私钥的本地上游 CA。客户端是否信任调试 CA 由用户处理，不静默修改系统信任，不绕过证书固定。
- 调试 CA 归私有目录；会话只保存方法、主机、端口、状态、协议、失败标记等元数据。禁用工具的流量明细打印，避免正文 / 路径 / 参数 / 认证头写入自有记录；界面显示最后 100 条，文件限制约 2 MB。
- 切换 / 停止主引擎时停止独立调试。进程就绪和真实 HTTPS 成功分开表达。内置抓包仍不解密外部模式，诊断结果引导进入独立调试。

### 限时分享任务

## 19. 第四轮实际交付：首页直接入口与公司内网

### 从资源任务进入，兼容不同公司的工具

- 总览首屏提供“分享本地服务”“工具与致谢”“公司内网”三个入口。公司小组件提供公司切换、资源打开和直接检查；完整配置在独立面板中，已保存配置优先展示连接动作与常用资源，编辑项默认折叠。
- 接入方式包括已有任意客户端 / 办公网、已配置系统 VPN、浏览器 SSO、HTTP(S) 专用代理与 SOCKS5 专用代理。客户端通过选择已安装 `.app` 打开；系统 VPN 需主动读取本机配置并绑定 UUID；浏览器入口交给原有认证流程。
- 多公司保存、单公司启用；资源支持 HTTP / HTTPS / SMB / SSH、短主机名、IPv4 / IPv6。专用代理仅支持 Web 资源；账号、MFA、设备认证、PAC 和 NTLM / Kerberos 委托公司官方工具。保存配置、客户端启动、VPN 管理器返回、路径响应与业务登录成功分别表达。

### 最小范围的策略与恢复

- 客户端 / 系统 VPN 模式为资源主机添加精确 DOMAIN 直连规则，系统解析保留 VPN 的域名作用域；解析失败不回退到 Leapin 公共 DNS。操作系统的实际 DNS 去向仍由其配置决定。浏览器模式不添加网络策略。
- 专用代理模式只为已列出的主机添加独立 HTTP(S) / SOCKS5 出站；系统解析代理端点，目标域名由代理处理。拒绝本机监听回路、家庭资源重叠、URL 凭据和无效配置。通过浏览器打开前检查系统代理状态与已知 bypass。
- 策略适用于原生 TCP 前门和 Mihomo 桥接前门，不改变来源配置、不配置系统 DNS / 网段 / UDP / 独立终端 TUN。切换与暂停影响新连接，不关闭用户已连接的公司客户端或 VPN。
- 私有文件原子写入、0600 权限、草稿基线检查；应用失败恢复先前配置。检查代次与引擎上下文绑定，取消、切换公司或更改网络后丢弃过期结果。

### 检查证据与团队复用

- 客户端 / VPN：系统解析 → TCP 端口 → Web 根地址 HEAD；专用代理：代理端点系统解析 / TCP → 经运行中的 Leapin 代理 HEAD；浏览器：操作系统正常网络路径 HEAD。SMB / SSH 仅端口检查，不执行登录或挂载。
- 不使用完整路径、参数、Cookie 或账号，不跟随跳转，不关闭 TLS 校验；区分认证要求、代理认证、根地址不支持 HEAD 和网络失败。结果记录时间，只说明取得的证据。
- 版本化团队 JSON 模板导入仅带入草稿；导出不含本机 `.app` 路径、VPN UUID 或专用账号字段。完整资源 URL 与备注会保留，界面提示审阅后分享。系统 VPN 模板需要本机重新绑定服务。
- 本轮全量 293 项、0 失败、1 项性能门禁跳过；真实本地 HTTP、专用代理、Mihomo 桥接和重载路径已验证。隔离原生 UI 实测模板导入 → 保存 → 首页小组件 → 分层检查，源站仅收到不带路径参数的 HEAD `/`。真实公司 VPN / SSO / MFA / 设备准入、跨公司网络冲突和厂商客户端仍待实际环境验收。
