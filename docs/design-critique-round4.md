## 2. 是否达到 8.0

**否。7.48，差 0.52。** 而且差的不是均值，是条款：

> 获奖线要求"任何一维不低于 7.7"。现在 **5 个维度在 7.1–7.3**（Typo 7.2 / White 7.1 / Motion 7.2 / Micro 7.2 / Resp 7.3），最短的那一维（Whitespace 7.1）差 0.6。

性质判断：**这不是"还缺一个想法"，是"收尾没扫干净"。** 理由：

1. Color（8.0）与 Originality（8.2）已经在获奖线上——单信号色纪律成立，双向地震仪是只有网络工具才有的器物，这两个最难的东西**已经做出来了**。
2. 卡住的全是**执行一致性与空态质量**：骨架屏的语义、刻度尺的可读性、同一组件两套对齐、分组第一处 6pt 的破功。这些没有一条需要新设计判断。
3. 一个常被忽略的**交付证据缺口**：15 张截图里代理全部处于「已停止」，抓包 0 条、SSH 未连接、NAS 无设备、隐私无样本、总览流量图只剩一根 2pt 红色游标。**签名器件在整份交付物里从未以工作态出现**——评委只能看到"它长这样"，看不到"它跑起来这样"。这不是代码缺陷，但它直接压住了 Originality 与 Motion 能拿到的分（否则两项都该更高）。

## 4. 剩余缺陷（5 条，均指到文件 / 像素）

### 4.1 隐私页读数系统：刻度尺数字读不出、三个读数不在一条光学线上（Typography + Color + Hierarchy）

- **现象一**：`0 / 55 / 80 / 100` 四个刻度标签是 mono 9pt 三级字，**又整条叠了 0.55 不透明度**（PrivacyView.swift:79 对 `scoreRuler` 整体 `.opacity(hasSample ? 1 : 0.55)`），实测等效色 ≈ rgb(174,172,164)，对比度 **≈2.1:1**。这一行本来是用来解释"55 / 80 是及格与良好线"的，现在等于隐形。
- **现象二**：同一张卡片的读数格里，`已拦截` 与 `风险项` 是「—」、`拦截规则` 是「0」，而 `metric()` 给占位符 20pt、给真数字 26pt（PrivacyView.swift:160）。结果是两个 19×4px 的短横杆浮在一个 26pt 的 "0" 旁边，**行看起来是坏的**，不是"留空"。
- **为什么算缺陷而不是"克制"**：克制是指不放 100 分假分（这轮做到了）；而刻度和占位符**存在的唯一理由就是被读到**。读不到 = 该删的没删、该保的没保。
- **验收**：无样本时标签回到 ≥4.5:1（去掉整条 opacity，只压暗尺身与填充）；占位「—」与真数字同字号（都用 26pt，或都用 21pt 从属档），基线对齐。

### 4.2 空态骨架屏：10 行幽灵骨架正在承诺一个永远不会来的加载（Whitespace + Micro-interaction）

- **总览**：`最近连接 / RECENT` 空态渲染 3 行永久骨架（DashboardView.swift:702-717，`Capsule` 填 `LP.text.opacity(0.07)`，高 7pt），下面才是"代理未启动，把系统流量指向 127.0.0.1:7,890 后即可记录"。
- **抓包**：同款但 7 行（CaptureView.swift:238-253，0.08 ink、整栈再叠 0.55 不透明度），**面板顶部钉 7 行灰条，底部栏才是真文案 + 朱红 CTA，中间约 130pt 空白**（量得：最后一行 ~y1050，底栏起 ~y1310，面板 y 363-1455）。用户的视线落在灰条上，需要跨过 130pt 才能读到"暂无 HTTP 请求"。
- **语义问题**：骨架屏 = "正在加载"的承诺。这里它是**永久态**，且 `Spacer(minLength: 0)` 把它顶死在顶部。第一次打开的人会等它加载完。
- **验收**：空态删掉骨架（或改成 3 行极淡的表格网格线，无 capsule、无 0.55 叠层），文案与 CTA 上移到首屏垂直中枢（面板 40% 高度处），而不是沉底。

### 4.3 规则表丢了"账页"语法：无行线 + 380pt 空走 + 107pt 空面板（Whitespace + Originality）

- **现象**：整张表**没有任何行分隔线**。实测 y 430-1250、x 900-1360 区间内只有两条横线：面板描边（366 / 1455）和表头下 0.5pt 的 #ECEBE8（y=426）。源码同源：`LazyVStack(spacing: 1)` 无逐行 hairline，只有表头上一条（RulesView.swift:178-180）。
- **后果**：9 行 32pt 节距的 mono 数据漂浮在 ~28pt 的空白里，而**策略列距匹配值约 380pt**（表头 `Spacer(minLength: 8)` + 右对齐构造）。跨行读"这行是 PROXY 还是 DIRECT"要靠肉眼保持水平线——这正是行线存在的理由。Direction 叫"Editorial Instrument"，账页/表格是没有行线的，而这张表**有**行线才像账页。
- **另一半**：`ScrollView` 把面板撑到页高 544pt，9 行在 ~y1240 结束，**留 107pt 带描边的空面板，没有 footer、没有合计行、没有"共 9 条"**。空面板比空态更贵：它看起来像"还有内容没加载出来"。
- **验收**：加 0.5pt `LP.stroke.opacity(0.55)` 逐行线；面板高度改为内容自适应（`fixedSize(vertical:)` 或给最小高度而非撑满），底部加一行 mono 10 的 `共 9 条 · 按 # 排序 · ⌘F 聚焦` 收口。

### 4.4 侧栏分组节奏在"第一个选中项"处破功（Visual Hierarchy）

- **现象**：选中 `总览` 时，`代理` 组标签距选中 pill 底边只有 **9pt**（实测 2× y：pill 底 389 → 代理标签顶 407 = 18px）；而 `观测 / 工具 / 系统` 三个组标签距上一项都是 **23pt**（~47px）。于是"代理"读起来像"总览"的子项，而不是平级分组。
- **根因**：`padding(.top, groupIndex == 1 ? 6 : 18)`（LeapinApp.swift:513）——为第二组单独写了 6pt。这行 fudge 大概是当初为压掉视觉空隙加的，但它是按"组序号"判断而不是按"上一项是否选中/是否 pill"，所以只要 总览 被选中就必现。
- **验收**：删掉这行三元表达式，统一 18pt；如果担心 `总览` 的 pill 让第一组显得松，就调 pill 的 `padding(.vertical)`，不要动组间距。

### 4.5 跨页对齐债：同一组件 / 同一类字段出现了两套对齐（Typography + Responsive）

三处同源问题，都属于"看起来没问题，但放在一起就露怯"：

1. **SSH 端口值居中**：`端口 / PORT` 的 "22" 在 92pt 宽字段里 `.multilineTextAlignment(.center)`（SSHView.swift:63-68），而右边 `用户 / USER` 的 "user" 是左对齐。结果 "22" 距自己的标签约 **31pt**，两个字段的下划线起点一致、文字起点不一致。
2. **学习页两栏顶部错位 11pt**：左侧 textarea 顶 y=380、右侧 dropzone 顶 y=358（2×），两个动作行 574 vs 585。左右栏是"方式一 / 方式二"的**并列**，顶部不齐会读成上下级。
3. **快捷键说明列参差**：设置页 chips 起点 x=1319，说明文字起点 1433 / 1371 / 1384 / 1433（**最大 31pt 参差**）；同一个组件在规则页 chips 1442、说明 1494 / 1507 / 1482 / 1494（12pt 参差）。同一结构两页两种对齐。

- **验收**：SSH 端口改左对齐（数值型字段左对齐 + 右对齐二选一，全页统一）；学习页两栏用同一条 `HStack(alignment: .top)` 基线并把 dropzone 与 textarea 同高起步；快捷键行改两列定宽（chip 固定 64pt + 说明统一左缘）。

## 5. 分维展开（为什么是这个分，不是更高/更低）

### 5.1 Typography — 7.2 / FAIL（差 0.5）

**已经对的**：页标题 22 semibold tracking −0.6、hero 34 tracking −1.1、正文 12/12.5 双档、mono 用于一切数据（IP、端口、规则值、字节数）——这套骨架比上轮扎实得多，圆角字体当正文的问题彻底消失，12pt 成为主力。

**为什么还差 0.5**：
- 字号**档数没变**（17 → 17）。非 mono 确实从 17 压到 8，但 mono 又散成 9 档；7pt 的 "NETWORK CONTROL"（LeapinApp.swift:616）在 2× 下只有 14px 高，是全仓最小的字。
- mono 8.5 被四个不同语义复用：侧栏组标签、地震仪轴标、右栏 meta、hover 键位提示。组标签是"结构"，轴标是"刻度"，键位提示是"操作"——三者同级于排版是错的。
- 隐私页 20pt / 26pt 混排（§4.1）是同一维度里的硬伤。

### 5.2 Whitespace — 7.1 / FAIL（差 0.6）

**已经对的**：1040 下抓包的 40% 空右栏**消失了**（上轮最大浪费），双栏页（设置 / 去广告 / 隐私）在 900 下仍保持两列且不挤。

**为什么还差 0.6**：剩下三处浪费都是"垂直的"，且都在视线落点上——抓包 130pt（§4.2）、规则 107pt（§4.3）、总览底部两张卡在 752pt 窗口里被硬切（无淡出、无"还有 N 项"）。横向已经很好了，纵向还停在"能放下就行"。

### 5.3 Visual Hierarchy — 7.6 / FAIL（差 0.1，最接近）

**已经对的**：5 组导航让"10 个平级页面"变成了有域的结构，这是本轮**信息架构**层面唯一的实质进步；仪器条（1 主 4 从、1×44 hairline 分隔）是全 App 最成熟的组件；每屏一个实心 CTA 基本守住。

**为什么还差 0.1**：
- 一屏三遍「已停止」：页头胶囊 `● 已停止`、hero chip `● 已停止 · 未接管流量 · 去广告`、侧栏状态卡 `● 已停止 / 混合 :7890 / DNS :5354 / ▶ 启动代理`。第三次尤其贵——它出现在**每一个页面**，把"状态"从"当前屏的信息"降成"常驻噪音"。
- 两个「启动代理」：hero 的实心朱红 + 侧栏状态卡的文字按钮。实心唯一性守住了，但同一个动作出现两次仍会让人犹豫"哪个是真的"。
- 去广告页：`去广告引擎` 标题右侧写 **未加载**，正下方四个开关**全开**（AdBlockView.swift:92 的 `engine.adblockActive` 与 config 开关是两套状态）。一眼看过去是自相矛盾——这不是文案问题，是两个状态源没被合并成一个叙述。
- 隐私页：hero 的 34pt「无样本」+ 全宽刻度尺把注意力拉向一个"没有值"的位置，而右侧那句真正的引导（"启动代理并浏览一会儿"）是 15pt、且被 dot 带着。**空态的层级应该反过来**：指令大、占位小。

### 5.4 Color — 8.0 / PASS 获奖线

**已经对的**：`#F6F4EF` 纸 + `#16150F` 墨 + `#C63A12` 朱红，暗色 `#0A0A0B / #151517 / #FF7A4D`；策略墨阶（DIRECT 常规 / PROXY 加粗 / 拦截才用朱红）是本轮最"专业工具"的一处；三处语义色 mint / amber / violet 从未同时出现在一屏。

**扣分点**：
- hero chip 行混了三种处理：`● 已停止`（dot + 文字）、`未接管流量`（灰底 Badge）、`去广告`（amber 底 Badge）——**同一行三种"状态表达法"**，而 amber 在别处是"警告"语义，这里却用在"功能已开"上。同一特性在上方 20pt 是朱红 switch，下方是琥珀 chip，两个颜色讲同一件事。
- 暗色下 amber Badge 的 10% 底叠成 **(41,37,30)**（实测于 dark-dashboard.png），与 `#E8B04A` 文字并存时是一块泥棕；文字对比本身够（约 7:1），但色块质感掉了。
- `使用中` 是全 App 唯一一枚 mint 底 Badge（ProfilesView.swift:274 / Shared.swift:99-114：10% 底 + 22% 描边）。别处状态都是 dot + 文字，这里破例。
- 暗色面板 `#151517` 与底 `#0A0A0B` 只差 2%，结构几乎全靠 12% 白描边撑——能看，但没有纸墨的"层"。

### 5.5 Motion — 7.2 / FAIL（差 0.5）

**已经对的**：地震仪 `rateCeiling = max(peak, ceiling × 0.94)` 每秒衰减 + `sqrt` 映射（DashboardView.swift:62-64 / :346-347）真正修掉了上轮"轴随峰值乱跳导致形态抽搐"的问题，这是**数据可视化级的正确**；页面切换 `opacity + offset(y:6)` 0.18s 也稳。

**为什么还差 0.5**：
- **曲线太多但语言太少**：33 处动画，25×`easeOut` / 6×`snappy` / 1×`spring` / 1×`easeInOut`。数量不是问题，"同一个动作在不同页面用不同曲线"才是。设计文档写了 5 行 motion table，代码里没有对应的 5 个常量。
- **reduceMotion 只覆盖 5 个文件**（Theme / Interactions / Shared / Privacy / AdBlock）。总览的 `contentTransition(.numericText())`、页面切换、抓包新行高亮**没有**守卫。这在 macOS 上是可提交缺陷，不是加分项。
- **零共享元素**：从总览点一条连接到抓包，没有任何 morph / 延展。全 App 最强的空间关系（列表 → 详情）没有动画表达。

### 5.6 Micro-interaction — 7.2 / FAIL（差 0.5）

**已经对的**：学习页 dropzone 现在有 `isTargeted` 反馈；解析按钮 `disabled` 走 ghost、可用才走 primary；LPSwitch 全站统一 32pt（上轮三种尺寸）；复制按钮 mint 勾 1.1s；badge / 行 hover 都在。

**为什么还差 0.5**：
- **按钮没有焦点环**：`LPPrimaryButtonStyle` / `LPGhostButtonStyle`（Theme.swift:251-287）里没有 `focused` / `isEnabled` 分支，也没有 `focusEffectDisabled`。键盘用户 Tab 到"启动代理"上看不到任何提示——而开关和输入框**都**有焦点态，这个不一致很刺眼。
- **LPRow 无按下态**（Interactions.swift:8-40 只有 hover 与 selected）。列表行点下去没有 0.985 的压缩或 0.86 的透明度，只有跳转。按钮有、行没有，是同一套手感里的断层。
- 空态骨架屏（§4.2）本质也是 micro-interaction 问题：**用"加载中"的语汇表达"没有数据"**。

### 5.7 Responsive — 7.3 / FAIL（差 0.4）

**已经对的**：900×700 三张图零溢出、零截断；侧栏 216 → 68pt 图标轨（保留 2×14 朱红胶囊 + 分隔线）、页头三控件并成单胶囊 `⌘K | 系统代理 ◯ | ● 已停止`、分组标签塌成 1px 分隔——这套窄宽坍缩是**工程完成度最高**的一块，比很多商业工具做得好。

**为什么还差 0.4**：
- **只设计了宽度，没设计高度**。700pt 下设置页/抓包页的卡片被窗口边缘**硬切**，没有淡出、没有"还有 N 项"、没有滚动阴影。macOS 上这是常态，但既然宽度做了三档适配，高度一档都不做就显得偏科。
- **抓包分栏的算术**：820 阈值 + 216 侧栏 + 64 内边距 → 需要窗口 ≥ 1101pt 才能看到详情栏。默认窗 1240 可以，但评审尺寸 1040 永远看不到——"<820 只留列表"是对的，**代价是详情页在标准窗宽下不可达**，且没有"点开用 sheet / 覆盖层打开详情"的兜底。这条不是让你改回分栏，是缺一条窄宽下的详情路径。
- 三处跨页对齐债（§4.5）里，学习页两栏错位本质也是布局问题，会随窗口宽度变化而放大。

### 5.8 Originality — 8.2 / PASS 获奖线

**已经对的**：「Editorial Instrument」不是皮肤，是**一套判断**——不要卡片阴影、要 hairline；不要多强调色、要墨阶 + 单一朱红；不要 glow、要顶部 44×2 的规则条（DashboardView.swift:156-162，实测红线 y 278-281 与面板描边 y=278 同排，是**压在边上的信号条**，不是浮空装饰）；数据不要图表、要"地震仪"。双向化之后（下载实线在上 / 上传虚线在下 / 共享 ceiling），这个器件终于只有 Leapin 有。

**为什么不是 8.5+**：
- **交付物里它从未工作过**。15 张截图全是空闲态，双向形态、端点圆点、图例实时数值一次都没出现。评委只能读到一根 2pt 红游标 + 一条几乎看不见的基线——这不是"克制"，这是"缺席"。
- 签名器件只出现在总览一页。抓包、隐私、规则都没有延续"仪器"的语言（规则表本来是第二个仪器位，现在是一张无行线的表，§4.3）。

## 6. 本轮做对了什么（不是客套，是记分）

1. **5 组导航是真的信息架构改动**，不只是加标题。快捷键保持 ⌘1–⌘0 原顺序也是对的取舍。
2. **双向地震仪的实现质量高于要求**：共享 rateCeiling + 每秒 6% 衰减 + sqrt 映射，三个细节合起来才让它"读起来像仪器"。
3. **规则页去 pill 是本轮视觉最干净的一处**（类型列纯 mono 大写 + 策略墨阶）。
4. **隐私页从"0 分给 100"变成"无样本"**，还配了"没有流量时显示「—」"的解释句——这是判断力，比任何字号修复都值钱。
5. **抓包 820 阈值**：右栏 40% 死区终究消失了（上轮 #1 问题）。
6. **上轮的假斜体疑虑被证伪**：hero 那句 serif 在中文下渲染为直立衬线（2× 裁切确认），`LPFont.serif(13.5).italic()` 仍是代码异味但没有可见缺陷——所以**没有**算进扣分。

## 7. 差 0.52：跨线要做的是这四件，不是"再修几个 bug"

> 未达 8.0，故按规则**不列"锦上添花"**。下面列的是"必须做"，不是"做了更好"。

| 优先级 | 做什么 | 推动哪几维 | 为什么是它 |
|---|---|---|---|
| P0 | 空态重做：删 10 行永久骨架，文案+CTA 上移到面板垂直中枢（§4.2） | Whitespace +0.4 / Micro +0.2 / Hierarchy +0.1 | 一次性修掉两处最大死白，且是"用户第一眼"的位置 |
| P0 | 字号谱收敛到真 10 档以内：删 7pt、把 mono 8.5 拆成"组标签 8.5 / 轴标 10"、13pt mono 全部归 12 | Typography +0.4 | 机械工程，收益最确定；档数不变是本轮最站不住的一点 |
| P1 | 按钮焦点环 + LPRow 按下态 + reduceMotion 全站守卫（§5.5/5.6） | Micro +0.4 / Motion +0.2 | 都是"一行代码级"修补，但决定"专业/业余" |
| P1 | 规则表加行线 + 面板高度自适应 + footer 合计（§4.3） | Whitespace +0.2 / Originality +0.1 | 把"账页"语法补齐，顺手把 107pt 空面板收掉 |

按 P0+P1 全部落地，粗算：Typo 7.6 / White 7.6 / Hier 7.7 / Color 8.2 / Motion 7.4 / Micro 7.6 / Resp 7.4 / Orig 8.3 → **7.73**（均值过线，但仍被 Responsive 7.4 卡住）。也就是说：**8.0 需要 P2 也做**，而 P2 恰好是最便宜的一条。

## 8. 一句话结论

**7.48 / 10 —— 设计语言已经立住（Color 8.0、Originality 8.2），拖后腿的全是收尾：空态在用"加载中"讲"没有数据"，字号谱换了地方却没变少，分组节奏在第一个选中项处塌了 6pt。再紧一轮，8.0 是可达的；现在提交，是一份"看得出品味、但没扫完地"的作品。**
