# ADR 001 · 首屏证据区先不做「最近决策」栏

- **状态**：accepted
- **谁定的**：PM（用户 2026-11-24 授权按 A 接手 T-17 余下部分）
- **触及**：T-17 的形态、`Sources/LeapinApp/Views/DashboardView.swift` 的首屏结构

## 在定什么

DESIGN-v5 §9 给「走哪」的目标是三段：页头 / 焦点带 / **证据区两栏（最近决策 7 : 场景 5）**。T-17 落地后，首屏的证据区只有场景一块。要不要现在把「最近决策」补上。

## 选项

**A. 用现有计数拼一条「最近决策」。** 比如「最近拦截 N 次」「规则 M 条在判」。
- 成本：半小时。
- 否决理由：这四项已经在焦点带里讲过一遍，换一种句式再讲不叫历史。它会给出「看起来像记录、其实是当下事实」的行 —— 首屏是最不该编的地方。

**B. 新建一条决策历史。** 谁在什么时候、依据哪条规则、把流量送去了哪个出口，落盘保存，首屏读最近三条。
- 成本：一条独立任务（引擎事件流 + 存储 + 裁剪策略 + 自己的采样纪律），比 T-17 本身大。
- 否决理由：T-17 的范围是「只改摆法」，接线不动。把它塞进这轮，等于用一次重排偷偷加一个数据层。

**C. 先不做，等真有来源再补。** —— 采纳。

## 为什么是 C

仓库里现在没有任何「决策」数据源，这是查过的事实，不是印象：

- `ResidentStatus` 只有当下四项（配置 / 出口 / 速率 / 拦截数）加覆盖范围，没有历史；
- `NetworkTask` 是各页面自己的临时任务态（`NetworkAssistantModel.task`），不是历史，也不跨页；
- `Workbench` 存的是工作区（探测、诊断、复测的上下文），不存判定。

没有来源的时候，「最近决策」只能是编的；而第一个该说真话的位置就是首屏。所以宁可少一栏，先空着。

## 后果

- 首屏证据区目前只有场景一块；DESIGN-v5 §9 的 7:5 两栏只兑现了 5 那一半。这一点写进了 T-17 的进度行与 CHANGELOG 的「已知」。
- 真要补，前置条件是先有一条能回答「谁、何时、依据什么、去了哪」的记录。那是一条独立任务，不是一次摆法调整。
- 现在不做不等于以后不做；写在这里，是为了下次有人问「这页为什么少一栏」时不必重新论证一遍。

## 备查

同时删掉的还有四段死代码：`statusBar` / `factStrip` / `factCell` / `factDivider`（焦点带接管后无人调用，约 96 行），以及从未被使用的 `textAction`。它们留在文件里不影响编译，但会让「首屏有几块」这类结构判据失真。
